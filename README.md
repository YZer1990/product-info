## ⚠️ 這個網站是公開的

GitHub 免費帳號的 Pages 只能架在 public repo 上，代表**任何知道網址的人都能開啟，也可能被搜尋引擎收錄**。

請勿放入：客戶名單、未公開營運數字、合約與報價、帳號密碼、內部人事資訊。

> git 會保留完整歷史。**檔案刪掉，舊版本仍留在歷史紀錄裡查得到**，不等於刪除。誤上傳敏感內容請立刻告知 Michael 處理，不要只是刪檔重推。

## 分工（重要）

這份 repo 直接放在網路共享資料夾裡，好處是同事不用裝任何工具、開網路芳鄰改檔案就好。代價是 git 沒有多人檔案鎖保護，所以分工必須固定：

| 誰 | 做什麼 | 不要做什麼 |
|---|---|---|
| **同事** | 開共享路徑、直接編輯 `.html` 檔並存檔 | 不要碰 `.git` 資料夾；不要執行任何 git 指令 |
| **Michael** | 檢查改動 → commit → push 到 GitHub | — |

也就是：**同事負責改內容，Michael 負責發布。** 改完請跟 Michael 說一聲，他 push 之後網站才會更新（不是存檔就上線）。

`.git` 是隱藏資料夾，存放整份版本歷史。**誤刪會整份歷史消失**，請不要動它。

## 同事怎麼改（零學習成本版）

1. 檔案總管網址欄貼上 `\\MICHAELLEE-PC\資料分享區\產品訊息`
2. 找到要改的 `.html` 檔，用 VS Code 或記事本開啟
3. 改完存檔
4. 告知 Michael 已改好

避免互相蓋掉的約定：

- **一人一檔**：各自負責不同檔案，盡量不要兩人同時開同一個 `.html`
- 真的要改同一個檔，先在群組講一聲，改完馬上說，不要開著過夜
- 共享資料夾沒有「復原」功能，改壞了要靠 Michael 從 git 歷史還原 —— 所以每次改完都要讓他 push，push 過的版本才救得回來

## Michael 的發布流程

在 GitHub Desktop 裡：

1. 左側選 `product-info`
2. 確認 Changes 清單裡的改動符合預期（點檔案可看到逐行差異）
3. 左下角填一行說明，例如「更新 8/5 產品訊息」
4. 按 **Commit to main**
5. 按 **Push origin**
6. 等 1～2 分鐘，開網址確認（必要時 Ctrl+F5 強制重新整理）

## 常見問題

**push 完網頁沒變？**
先等 2 分鐘（GitHub 需要時間重新發布），再按 Ctrl+F5。仍沒變的話到 repo 的 Actions 分頁看有沒有發布失敗。

**可以直接在 GitHub 網頁上改嗎？**
可以，repo 裡點檔案 → 鉛筆圖示 → 改完 Commit changes。但這樣改完，共享區這份會變成舊版，Michael 要記得先 Fetch origin 把它拉回同步，否則下次 push 會衝突。**同事請不要用這個方式**，一律改共享區的檔案。

**能不能讓網頁上直接編輯內容？**
不行。GitHub Pages 是純靜態網站，沒有後端可以存資料。要那種功能得改用別的服務。
